## 1. Как устроен шаблон кейса

Страница `/projects/<slug>` собирается из полей ниже. **Поле без данных не выводится.** Это честнее, чем заполнять пустоты общими словами.

| Блок на странице | Поле в `projects.ts` | Обязательно | Что писать |
|---|---|---|---|
| Заголовок | `title` | да | Тип клиента без названия, пока нет разрешения: «Промышленный подрядчик». Не длиннее ~24 знаков, иначе на телефоне заголовок занимает 3 строки |
| Подзаголовок | `task` | да | Одна фраза: что нужно было сделать |
| Факты справа | `industry`, `kind`, `year` | `year` — нет | Отрасль, тип работ, год |
| Ссылка на сайт | `url` | нет | Только при разрешении клиента |
| О компании | `business` | да | 1–2 предложения о бизнесе клиента |
| Задача | `goal` | да | Запрос клиента своими словами |
| Аудитория | `audience` | да | Кто пользуется сайтом. Если это ваше предположение, а не данные клиента, — так и написать |
| Проблема | `problem` | да | Что мешало до проекта |
| Роль исполнителя | `role` | да | Что делали лично вы; в составе какой команды или студии |
| Ограничения | `constraints` | нет | Сроки, CMS, готовый стиль, контент |
| Исследование | `research` | нет | **Только проведённое.** Не было исследования — поле удаляется |
| Сценарии и структура | `architecture` | нет | Ключевые сценарии, карта страниц |
| Прототипирование | `prototyping` | нет | Что прототипировали, что поменялось после согласования |
| UI-концепция | `uiConcept` | нет | Почему визуальное решение такое |
| Ключевые решения | `decisions[]` | нет | 3–5 решений: «сделали X, потому что Y» |
| Адаптивные состояния | `adaptive` | нет | Что специально сделано для телефона |
| Изображения | `images[]` | нет | Файл, размеры, alt, подпись. См. §3 |
| Результат | `outcome` | да | Что запущено и когда |
| Подтверждённые результаты | `results[]` | нет | **Только с подтверждением:** цифры из аналитики, письменный отзыв с разрешением на публикацию |
| Выводы и что дальше | `conclusions` | нет | Что получилось, что бы улучшили. Предложения не выдаются за сделанное |

**Черновики.** Текст, который ждёт данных, начинается с `[ЧЕРНОВИК]`. На странице он показывается жёлтой плашкой «Черновик.». У кейса со `status: "draft"`:
- жёлтая полоса «Черновик кейса» под вступлением;
- заглушки на месте изображений;
- `noindex` в метатегах.

После заполнения поменять `status` на `"published"`.

## 2. Анкета по каждому кейсу

Скопируйте блок, заполните и пришлите. Ненужное — удалите. «Не знаю» — тоже ответ: поле просто не выведется.

```

Сайт: (адрес) — можно показывать ссылку? да / нет

Разрешение на публикацию в портфолио: есть / нужно запросить / нельзя
Год:

Ваша роль (отметьте): аналитика · структура · прототипы · UI-дизайн · вёрстка · разработка · интеграции · другое:
Работали: самостоятельно / в составе студии (какой) / с кем ещё

Задача клиента (своими словами):
Что было не так до проекта:
Кто пользуется сайтом:

Почему дизайн такой:

```

## 3. Изображения кейсов

| Что | Требование |
|---|---|
| Формат | PNG или JPG от 1920 px по ширине. Оптимизацию в WebP/AVIF делает Next.js |
| Состав набора | Обложка 16:9 (главный экран), схема структуры, прототип, макет десктопа, макеты телефона |
| Права | Только собственные макеты или скриншоты с разрешения клиента. Чужие фото и логотипы внутри скриншота — по согласованию |
| Alt | Что изображено: «Главная страница каталога: категории техники и строка поиска» |
| Подпись | Что видно и почему это важно, одной фразой |

Первое изображение в `images[]` становится обложкой карточки на главной и в `/projects`.
