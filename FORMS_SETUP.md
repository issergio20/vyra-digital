# VYRA Digital — настройка приёма заявок

Статус: **BLOCKED** — получатель заявок не выбран. Форма и сервер готовы. Пока переменные окружения не заданы, сервер отвечает `503 not_configured`, а форма показывает «Приём заявок через сайт ещё не настроен. Заявка не отправлена». Ложного подтверждения нет.

---

## 1. Как устроено

```
Форма (/contacts#brief)
  → проверка в браузере (та же схема zod, что на сервере)
  → POST /api/brief (JSON, до 16 КБ)
  → проверки сервера: служебные поля → повтор по requestId → время заполнения ≥ 3 с
    → данные формы → лимит 5 заявок за 10 минут с одного IP → есть ли получатель
  → доставка в Telegram
  → 200 только после успешной доставки
```

| Файл | Что делает |
|---|---|
| `site/src/lib/brief-schema.ts` | Поля, правила и тексты ошибок — общие для браузера и сервера |
| `site/src/lib/brief-handler.ts` | Логика приёма: антиспам, повторы, лимит частоты, ответы |
| `site/src/lib/send-brief.ts` | Текст заявки и отправка в Telegram |
| `site/src/app/api/brief/route.ts` | Обработчик `POST /api/brief` |
| `site/src/components/forms/ProjectBriefForm.tsx` | Форма и её состояния |
| `site/tests/unit/*.test.ts` | 25 юнит-тестов (`npm test`) |

**Ответы сервера**

| Код | `code` | Когда | Что видит посетитель |
|---|---|---|---|
| 200 | — | Заявка доставлена | «Заявка отправлена» |
| 400 | `invalid` | Ошибки в полях | Ошибки под полями |
| 400 | `bad_request` | Нет служебных полей или неверный JSON | «Обновите страницу и попробуйте ещё раз» |
| 413 / 415 | `bad_request` | Слишком большой запрос или не JSON | Общая ошибка |
| 422 | `spam` / `too_fast` | Заполнена ловушка или форма отправлена быстрее 3 с | Сообщение с просьбой повторить |
| 429 | `rate_limited` | Больше 5 заявок за 10 минут с одного IP | «Попробуйте через 10 минут» |
| 502 | `delivery_failed` | Telegram не принял сообщение | «Не удалось доставить заявку» |
| 503 | `not_configured` | Получатель не настроен | «Приём заявок ещё не настроен» |

**Персональные данные.** Заявка нигде не хранится — только пересылается. В лог сервера пишется лишь факт сбоя и название канала, без имени и контакта (проверено тестом).

## 2. Что нужно от вас: Telegram-бот (рекомендуется)

Бесплатно, без дополнительных библиотек, заявка приходит за секунды.

1. В Telegram откройте **@BotFather** → `/newbot` → задайте имя (например, «VYRA заявки»). Получите **токен** вида `123456:ABC…`.
2. Напишите своему боту любое сообщение (например, `/start`) — иначе бот не сможет вам писать.
3. Узнайте свой **chat_id**: откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":…}`. Для группы: добавьте бота в группу, напишите в ней сообщение и повторите запрос — id группы начинается с минуса.
4. Создайте файл `site/.env.local` (он не попадает в Git) по образцу `site/.env.example`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_CHAT_ID=123456789
   ```
5. Пересоберите и запустите сайт: `npm run build`, затем `npm run start`.
6. Отправьте тестовую заявку на `/contacts` — она должна прийти в Telegram, а на сайте появится «Заявка отправлена».

На хостинге эти же переменные задаются в панели управления, а не файлом.

**Токен — секрет.** Не присылайте его в чат и не коммитьте. Если токен утёк — `/revoke` в @BotFather.

## 2а. Запасной канал: e-mail на странице контактов

Если форма не смогла отправить заявку (приём не настроен или Telegram недоступен), под ошибкой появляется кнопка «Скопировать текст заявки» — посетитель не теряет написанное. Если задать адрес, рядом появится «Отправить письмом» (письмо с готовым текстом), а сам адрес — в «Прямых контактах» вместо черновой плашки:

```
NEXT_PUBLIC_CONTACT_EMAIL=почта@вашдомен
```

Адрес публичный (виден в коде страницы), это не секрет. После изменения — пересборка.

## 3. Почта (альтернатива или в дополнение)

Отправка по SMTP требует библиотеки (например, `nodemailer`) и почтового ящика на домене. Пока не подключено, чтобы не добавлять зависимость без решения. Если нужна почта:

- ящик на домене (Яндекс 360, Mail.ru для бизнеса и т. п.) и пароль приложения;
- записи SPF и DKIM для домена, чтобы письма не попадали в спам;
- тогда добавлю транспорт `smtpTransport` рядом с `telegramTransport` в `send-brief.ts`. Если настроены оба канала, заявка считается доставленной, когда её принял хотя бы один.

## 4. Ограничения

- Лимит частоты и защита от повторов хранятся в памяти процесса. На нескольких серверах или после перезапуска счётчики обнуляются — для небольшого сайта это допустимо.
- Капча не подключена: ловушки и проверки времени обычно достаточно. Если появится спам — следующий шаг Яндекс SmartCaptcha (сторонний сервис, нужно упомянуть его в политике).
- Политика конфиденциальности должна назвать сервис, через который проходит заявка (Telegram). Сейчас это черновик в `/privacy`.

## 5. Калькулятор стоимости — решение

Отдельный калькулятор **не делается** (ТЗ §18):
- надёжной формулы цены нет: цены предварительные и ещё не проверены спросом ([VALIDATION_PLAN.md](VALIDATION_PLAN.md), гипотеза H8);
- псевдоточная сумма пообещала бы то, чего нет.

Вместо него на главной и на `/pricing` работает выбор задачи: пакет → срок и цена «от» из одного файла `content/packages.ts`, с пометкой «Ориентир; точная смета — после брифа». Вернуться к калькулятору — когда наберётся 3+ закрытых проекта и станет понятно, от чего реально зависит цена.
