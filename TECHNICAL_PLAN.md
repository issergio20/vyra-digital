## 4. Формы и приём заявок

**Схема:** форма → `POST /api/brief` (Route Handler) → валидация zod → антиспам → отправка получателю → ответ клиенту. Сообщение «Заявка отправлена» показывается **только после ответа 200 от сервера**.

| Требование ТЗ | Реализация |
|---|---|
| Валидация на клиенте и сервере | Одна zod-схема |
| Защита от повторной отправки | Кнопка блокируется на время запроса; idempotency-ключ формы на сервере |
| Антиспам | Скрытое поле-ловушка (honeypot) + минимальное время заполнения + ограничение частоты по IP. Капча — только если появится спам (сторонний сервис = доп. обработка данных) |
| Минимизация ПДн | Только имя, один контакт, описание; бюджет и срок — необязательны. Ничего не храним в базе — только пересылаем |
| Согласие на обработку ПДн | Чекбокс + ссылка на /privacy |

**Получатель заявок — нужно выбрать (BLOCKED до решения):**

| Вариант | Что нужно от вас | Плюсы | Минусы |
|---|---|---|---|
| A. Telegram-бот | Создать бота у @BotFather, токен и chat_id → в переменные окружения | Бесплатно, мгновенно, не нужен почтовый сервер | Зависимость от Telegram |
| B. E-mail через SMTP | Почтовый ящик на домене (например, Яндекс 360 / Mail.ru для бизнеса) и пароль приложения | Привычно, заявки хранятся в почте | Нужно настроить домен (SPF/DKIM) |
| C. Оба | A + B | Надёжность | Больше настройки |

Рекомендация: **C или A** на старте. Секреты — только в переменных окружения (`.env.local`, не в Git); в репозитории — `.env.example` с пустыми значениями.

Если получатель не настроен — форма показывает ошибку «Не удалось отправить, напишите напрямую: …», а не ложный успех.

## 5. Хостинг (решение за вами)

Обработчик формы требует серверной среды (Node.js или serverless).

| Вариант | Комментарий |
|---|---|
| Российский облачный хостинг с Node.js (Timeweb Cloud Apps, Yandex Cloud Serverless, VPS) | **Рекомендуется**: 152-ФЗ требует, чтобы первичная запись персональных данных граждан РФ велась в базах на территории РФ. Мы не храним заявки в БД, но сервер, который их принимает, лучше держать в РФ. Ориентир: от ~300–600 ₽/мес (проверить тарифы) |
| Vercel / Netlify | Проще деплой, бесплатный тариф. Риски: доступность из РФ, оплата, 152-ФЗ |
| Статический экспорт + внешний сервис форм | Дешевле всего, но форма зависит от стороннего сервиса и его политики данных |

Публикация — **только после вашего разрешения** (требование ТЗ §21).

Юридическая оценка 152-ФЗ — не моя компетенция; формулировки политики конфиденциальности стоит показать юристу.

## 6. SEO и производительность (план)

- Метаданные через `generateMetadata`; canonical на всех страницах; Open Graph-изображения генерируются.
- `sitemap.xml`, `robots.txt` — генерируются из списка маршрутов и контента.
- JSON-LD: Organization, BreadcrumbList, FAQPage, Service — только по фактическому содержимому.
- Шрифты — самохостинг через `next/font`, только нужные начертания с кириллицей, `font-display: swap`.
- Изображения кейсов — `next/image` (AVIF/WebP, размеры, lazy loading ниже первого экрана).
- Максимум статики: клиентские компоненты только там, где нужна интерактивность (меню, аккордеон, форма).
- Цели (проверяются замером, не обещаются): LCP < 2,5 с, CLS < 0,1, INP < 200 мс на мобильном профиле Lighthouse.
- Аналитика — Яндекс Метрика **только по вашему решению** (сторонний трекер требует cookie-уведомления и упоминания в политике).

## 9. Команды (после инициализации)

```
npm run dev        # разработка
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
npm run test       # Vitest
npm run test:e2e   # Playwright
npm run build      # production build
npm run format     # Prettier
```

Все команды запускаются из папки `site/`. E2E поднимает production-сервер на порту 3200 и использует установленный Chrome (`channel: "chrome"`); перед `test:e2e` нужен `npm run build`.
